# 秋招填表助手 · Jobhunt Filler

一个 Edge / Chrome 扩展。在**你自己的浏览器、你自己的登录态**里把网申表格填好，然后停在提交按钮前面。

**最后那一下永远由你点。**

---

## 它做什么

| 功能 | 说明 |
| --- | --- |
| 自动填表 | 大模型只判断「页面上这个字段对应简历里的哪一项」，真正写值、匹配选项、处理日期控件全在本地脚本里做 |
| 三种填充模式 | 整页填充 / 增量填入（跳过已有值）/ 选区填入（先框选再填） |
| 一键存岗位 | 从当前页面认出公司、岗位、城市、岗位描述，存进本机的[求职看板](../jobhunt-desk) |
| 提交前检查 | 列出还空着的必填项并在页面上标红，包括标签只画了个星号、DOM 里没有 `required` 的那种 |
| 手工更正回写 | 你改过的字段会被记下来，下次填同一页直接按你改的填 |
| 多份简历模板 | 按赛道各留一份（公募中台 / 出海战略 / 外资行），填之前选一份 |

## 装上它

1. 打开 `edge://extensions/`（Chrome 是 `chrome://extensions/`）
2. 打开右下角的「开发人员模式」
3. 点「加载解压缩的扩展」，选中这个目录
4. 点扩展图标，右边会出来侧边栏

没有构建步骤，源码目录直接就能加载。

### 配模型

侧边栏右上角齿轮 → 填 Base URL / API Key / 模型 ID。任何 OpenAI 兼容接口都行（DeepSeek、通义、Kimi、本地 Ollama + LiteLLM）。

Key 只存在这台电脑的扩展本地存储里，不走浏览器账号同步，也不会传给页面脚本——所有请求都从扩展后台发出去。

### 准备标准简历

侧边栏「标准简历」→「打开简历配置页」。可以手填，也可以粘简历原文或传带文字层的 PDF 让模型先整理一遍，整理完自己核一遍再保存。

## 和求职看板配合

看板是隔壁那个项目（`jobhunt-desk`），跑在你自己电脑上。

```bash
cd ../jobhunt-desk && python3 run.py
```

然后在侧边栏「岗位与看板」里点「测试连接」。默认地址 `http://127.0.0.1:8765`，端口换过就在那里改。

**只允许本机地址**：填别的域名会被打回默认值。看板里是你全部的求职记录，不该往别处发。

一次网申大致是这样：

```
看到一个岗位  →  点「一键存进看板」   （岗位进了看板，状态「想投」）
点开网申页    →  点「开始填充」       （表格填好，需要你确认的标黄）
              →  点「检查必填项」     （还空着的标红，滚到第一个）
              →  你自己点提交
              →  点「标记为已投」     （看板状态改成「已网申」，自动记下日期）
```

## 手工更正回写是怎么回事

原来的映射缓存只省模型调用，不学东西：你手改过的字段，下次填同一页还是按老映射覆盖回去，每次都得返工。

现在填完之后会盯一下那个控件。你要是把值改了，就记下「这一页的这个字段 → 你改成的值」，下次直接按你的来，日志里会写一行 `[更正] …`。

记的是**值**不是简历路径——你手改的原因通常是「母版里没有这个东西」或者「这家要的写法不一样」，记路径解决不了。

觉得记岔了：侧边栏「岗位与看板」→「清空更正记录」。

## 它不做什么

- **不自动提交表单。** 代码里没有任何 `form.submit()` / 点提交按钮的逻辑，连深度扫描展开折叠区块时都专门把 `type="submit"` 和带「提交/保存/新增」字样的按钮排除在外。
- **不绕人机验证。** 验证码由你自己看短信、自己输。
- **不在禁止插件的平台上跑。** BOSS 直聘这类明确封号的站点，不要在上面用。
- **不上传文件。** `input[type=file]` 只会被列进检查清单提醒你，不会替你传。
- **不编造。** 填进去的值只来自你的标准简历，母版里没有的就留空并标红。
- **不联网到第三方。** 除了你自己配的那个模型接口和本机看板，不发别的请求。

## 测试

```bash
npm test          # 125 个单元 / 集成测试，零依赖，node ≥ 20
node e2e/run.mjs  # 浏览器里的端到端检查（需要 playwright）
```

`npm test` 里有一组是真的起一个求职看板的 Python 服务器，让扩展的客户端去打它，跑完整的「存岗位 → 去重 → 回写已投」。看板项目不在旁边会自动跳过。

`e2e/run.mjs` 会把扩展真的加载进 Chromium：确认 manifest 和 service worker 没问题、侧边栏没有 JS 报错、并在一个仿真的网申页面（`e2e/test-form.html`）上跑通存岗位和必填检查，最后确认表单**没有**被提交。截图落在 `e2e/shots/`。

> 这套端到端不是摆设。「标签带星号算必填」这条规则最初就是在这里被发现从来没生效过——上游的标签提取器在判断之前就把星号洗掉了。单元测试发现不了，因为它直接喂的是带星号的标签。

## 来历与许可

本项目基于开源项目 **AI-Resume-Form-Filling-Assistant**（GPL-3.0）改造，保留原 `LICENSE`。

在原项目基础上做的改动：

- 删掉了 `modules/` 和 `templates/` 整套站点模板机制——那是上一个「问卷自动答题」项目的残留，约 550 行，跟简历填表主链路没有任何连接
- 新增一键存岗位、提交前必填检查、手工更正回写三项功能
- 侧边栏加了「岗位与看板」页签

因为是 GPL-3.0，改造版同样以 GPL-3.0 发布。

### 还没解决的两个问题

诚实地说清楚，免得用的时候撞上：

1. **不支持 shadow DOM 和 iframe。** 有些招聘系统的表单在这两种结构里，扫不到字段就填不了。遇到这种页面只能手填。
2. **日期控件的适配是围着美团的设计系统写的**（`content.js` 里能看到写死的 `.mtd-input-affix-wrapper`）。别家的日期面板大概率要单独适配。

另外：缓存未命中、需要调模型建立映射时，简历里所有非空字段的值（每个最多 120 字符）会随请求发给你配的那个模型。本地日志做了脱敏，但发出去的 payload 没有。介意的话用本地模型。
